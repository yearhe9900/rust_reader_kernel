# 设计-检索与 BM25 索引

> 对应 issue #9。术语与《设计-Rust阅读内核总体方案》《设计-极速开书与渲染统一方案》对齐：
> 句柄（BookHandle）、语义坐标（SemanticPos）、扁平块（`flatten_blocks`）、
> 三要素缓存 key（content_hash / style_hash / viewport_hash）。

## 1. 定位

宿主（MReader）当前在 Dart isolate 里做全书搜索：逐章取文本 + 扫描。50MB 级大书受制于
「跨边界搬正文」与「Dart 侧二次分配」，体验有瓶颈。内核已有句柄表、零解压章索引
（`chapters()`）、按需取章（`load_chapter`），检索是天然下一步：**正文不出内核**，
跨 FFI 只传「批次命中 + 进度」。

两条能力分开成两个会话，互不依赖：

| 能力 | 会话 | 输入 | 输出 |
|---|---|---|---|
| 全书搜索 | `SearchSession` | 句柄 + 查询串 + 选项 | 分批 `SearchHit`（章 / 字节偏移 / 片段） |
| BM25 索引 | `Bm25Job` → `Bm25` | 句柄（逐章投喂） | 序列化索引字节 + 章级排序 |

## 2. 契约

### 2.1 文本真值：搜到的 = 读到的

宿主读到的段落文本来自 `rrk_model::flatten_blocks`（issue #4 定的唯一降维口径）。
若检索另走一份「按原文扫描」，就会出现「宿主看得见但搜不到」的偏差。因此：

- 检索与索引**都**消费 `flatten_blocks_spans`（`flatten_blocks` 的可追溯版本，
  两者文本内容完全一致，前者额外给出偏移映射）；
- 索引侧再用 `rrk_search::search_text` 去掉行内图片标记 `\u{FFFC}key\u{FFFC}`
  （非文本标记不该进词表），块间以 `\n` 分隔，避免跨块拼出伪词。

### 2.2 偏移坐标系

命中偏移一律是 `ChapterContent.text` 的 **UTF-8 字节偏移**——与目录锚点
（`TocNode.anchor`）、内链（`LinkRange.range`）、进度（`SemanticPos.char_offset`）
同一坐标系。宿主 UTF-16 映射归宿主（与既有约定一致，内核不引入第二套坐标）。

段落文本与章正文是两个坐标系（段落是行内序列拼接，且含图片标记），故需要回映：

```
章节正文  ──flatten_blocks_spans──▶  扁平块（plain 文本 + PlainSpan[]）
   ▲                                        │
   └──── PlainTextBlock::to_source(off) ────┘
```

`PlainSpan { plain: TextRange, src: Option<TextRange> }`：段落在块内 plain 文本的区间
与它在章正文里的区间一一对应；行内图片标记的 `src = None`（命中落在标记上时退到
最近的文本片段末尾，见 `source_anchor`）。

## 3. 全书搜索

### 3.1 拉模式分块

```
search_open(handle, query, opts) → search_id
search_next(search_id, max_hits) → { hits[], scanned, total, done }
search_cancel(search_id)
```

`search_next` 扫描到「凑够 max_hits」或「全书扫完」即返回，宿主按批消费。内核侧状态机：

```
next_chapter ──加载──▶ CurChapter{ blocks, block, offset }
                          │  ↑
                          └──┘ 块内 find 游标（块扫完推进 block；章扫完释放 CurChapter）
```

内存 O(1 章)：任何时刻只持有一章的扁平块，不缓存全书扁平文本。

### 3.2 取消要真停

- 会话表项 = `(Arc<Mutex<SearchSession>>, Arc<AtomicBool>)`；
- `search_next` **先取会话再放内核锁**，长扫描在会话锁内进行；
- `search_cancel` 只需内核锁（毫秒级）+ 置 `AtomicBool`，不必抢会话锁，因此
  正在扫描的调用会在下一个检查点（每章 / 每批）看到标志并返回 `Cancelled`(1005)；
- 会话从表中摘除后，内存随最后一个 `Arc` 释放，**不起后台线程**。

### 3.3 匹配与分词

- 匹配是**字面子串**（`str::find`），非正则；大小写不敏感时对双方做 ASCII 折叠
  （`fold_ascii` 只在有 ASCII 大写时分配，且**字节长度不变**，偏移映射不受影响）。
- 分词只用于 BM25：CJK 连续段取 bigram（单字段退化为 unigram），西文/数字按
  「字母数字块」整词并折叠小写。中文无词典分词下 bigram 是召回/精度最平衡的口径，
  且单字查询天然可命中。
- 图片章（`ChapterKind::ImageGallery`，CBZ）无正文，跳过但仍计入进度。

### 3.4 片段

`make_snippet`：命中左右各取 `context_chars` 字节（默认 30），起点/终点对齐 UTF-8
边界，两端截断补 `…`；同时返回片段在块内 plain 文本的起点（`snippet_offset`），
供宿主做局部高亮。

## 4. BM25 索引

### 4.1 构建

```
bm25_open(handle) → index_id
bm25_step(index_id, max_chapters) → { built, total, done, terms, bytes }
bm25_pull(index_id, offset, max_bytes) → 字节块 + next_offset
bm25_query(index_id, query, top_k) → [{ chapter, score }]
bm25_close(index_id)
```

- **doc = 章**（与 `chapters()` 同粒度），天然对齐「搜到章 → BM25 排序」；
- `step` 分批（宿主可传 32/256 章），建完那一步顺带完成序列化；
- 参数取业界默认 `k1 = 1.2`、`b = 0.75`，idf 用 Lucene 口径
  `ln(1 + (N - df + 0.5)/(df + 0.5))`（恒正，避免高频词负分）；
- 内存结构：`dict: HashMap<token, term_id>` + `terms: Vec<Vec<(doc, tf)>>`
  （postings 按 doc 升序追加，编码时转增量）。

### 4.2 序列化格式（v1，小端）

```
magic  "RRKI"    version u32=1
doc_cnt u32      total_tokens u64      term_cnt u32
docs    doc_cnt × u32        章 id（索引内 doc index → 章）
doc_len doc_cnt × u32        该章词项数（BM25 的 dl）
terms   term_cnt × {
          token_len u32, token bytes,
          df varint,
          df × { doc_delta varint, tf varint }   // doc_delta 相对上一个 doc
        }
```

`df`/`doc_delta`/`tf` 用 LEB128 varint：CJK bigram 词表里 tf 多为 1、章号增量远小于
2^14，实测比定长 u32 省约 61%（枭臣 7.1MB EPUB：24.5MB → 9.5MB）。

**内核不写盘**：`bm25_pull` 分块交给宿主，落盘/缓存/失效策略归宿主；
宿主重启后用 `bm25_load`（Dart `RrkBm25Index.load`）把字节交回内核，
`decode` 会校验 magic / 版本 / 结构边界，损坏即 `CorruptData`（隔离，不猜）。

### 4.3 实测量级（枭臣.epub，1152 章 / 7.1MB）

| 指标 | 数值 |
|---|---|
| 全书搜索（字面 "林缚"） | 23750 命中 / 204 ms（release，含 1188 批跨 FFI） |
| BM25 建索引 | 915 ms（release），380544 词项 / 3.34M 词项总量 |
| 索引体积 | 9.53 MB（varint）/ 24.57 MB（定长 u32，已弃用） |
| 载入 + 查询往返 | 112 ms，查询结果与内存索引逐条一致 |

TXT《大荒蛮神》（1077 章）：`蛮神` 命中 11 条，与全文原始出现次数**逐条对齐**（29 ms）。

## 5. 宿主接线

```
dart
├─ final s = book.search('林缚');               // 拉模式
│  do { final b = s.next(maxHits: 50); ... } while (!b.done);
│  s.cancel();
└─ final idx = book.buildIndex();               // 分步 / 可中断
   var p = idx.step(maxChapters: 256);
   while (!p.done) { p = idx.step(maxChapters: 256); }
   final bytes = idx.pullAll();                  // 宿主落盘
   final hits = idx.query('林缚 江宁', topK: 10);
```

MReader 侧按 `HighPerfCapability.fullTextSearch` / `bm25Index` 择优注册，失败回落现有
Dart 实现（Dart 基线长期保留，作回滚与无 Rust 环境回落）。

## 6. 明确不做

- **不写盘**：索引字节只交宿主，内核无缓存目录概念；
- **不做 UTF-16 映射**：偏移一律字节坐标系，转换归宿主；
- **不做词典分词 / 词干化 / 同义词**：中文 bigram + 英文整词，足够「找得到」；
  精度增强（词性、近义词）留给宿主层或后续索引版本；
- **不做增量索引**：书是静态的，重建成本 ≈ 1s/千万字，增量收益不抵复杂度；
- **不做拼音/模糊检索**：需求未定，且会显著放大词表。
