# 渲染层性能分析与按需渲染改造方案

> 基于现行代码实测（`lib/reader/pagination/*`、`lib/reader/reader_page.dart`、`lib/reader/chapter_cache.dart`、`lib/reader/image_cache.dart`）的瓶颈评估 + 可落地改造设计。回答五件事：现状渲染范围与资源占用、瓶颈在哪、按需渲染怎么改、改造/自研路线怎么走、边界与验收指标。

---

## 1. 现状：渲染方式、渲染范围与资源占用

### 1.1 双模式现状

| | 分页模式（`_pagedMode = true`） | ListView 模式（`_pagedMode = false`） |
| --- | --- | --- |
| 适用 | EPUB/TXT **文本章** | 图片章（异步图片高不进静态布局表，FMT-02 P1 未迁） |
| 结构 | `PagedScroller`：窗口 ±1 章页表拼**连续长卷** | 全部章节塞进**一个 `ListView.builder`**，每章一个 item |
| 几何 | `PagedLayout` 布局表一次算清（章顶/页顶/扁平页序/总高），滚动只做二分 | 估高 `_estimatedChapterHeight`（已布局子项均值），总高随构建漂移 |
| 落位 | `offsetForCharOffset` = 页顶 + 目标行行顶，单跳无校正环 | 段落 box 精校 + 粗估 |

主流路径是分页模式；ListView 是历史通道，其估高漂移本身是已知 bug 源（「进书从 40 多章跳到…」）。

### 1.2 分页模式的四层数据流

```
章正文(paragraphList)                    ChapterCache LRU 30 章（PERF-02）
   │  逐段 TextPainter 测量（root isolate，预算切片）
   ▼
行表 List<MeasuredLine> ──切页──▶ 页表 List<PageSlice>
   │  IncrementalPaginator：prime 16ms 突发出 5 页（kInitialPageCount）
   │  空闲帧 6ms/帧补完全章（kIdleFrameBudget）
   ▼
PaginationScheduler：当前章独占预算 → ±1 章预分页队列（freeze 冻结动画期）
   │  PaginationCache LRU 5 章 + setProtected（窗口章保护）+ 按 bookId 驻留
   ▼
PagedScroller：_computeWindow=[cur−1,cur,cur+1] 拼长卷
   │  可见区间 = 视口 ±1 页高 overscan（visibleRange 二分）
   ▼
Stack 只挂可见页：PageContent = ClipRect + OverflowBox(topLeft)
   + Transform.translate(−preHeight) + 相交段落完整 Column
```

### 1.3 渲染范围（实测口径）

- **widget 挂载**：已按需——`PagedScroller._buildLayer` 只挂 `[视口−1页, 视口+1页+视口高]` 区间的页 + 相交章标题；远离视口的页**即时卸载**（回收是即时的）。
- **页内渲染**：**不是按需**——每页 `PageContent` 渲染「页首行所属段落起 → 页末行所属段落止」的**完整段落**（`page_renderer.dart` 头注释自认：「页外内容被裁但不省排版」）。页外部分靠 ClipRect 裁掉，但布局成本照付。
- **页表驻留**：窗口 ±1 章的行表 + 页表全量在内存；`PaginationCache` 目标 LRU 5 章（保护集可超界）。
- **文本驻留**：`ChapterCache` LRU 30 章正文（`kEagerLoadRadius=12` 后台按距离补齐，批 3）。
- **图片驻留**：`ImageCacheLRU` 50MB **原始字节**（未解码）；解码位图另占 Flutter 全局 `ImageCache`（未纳管）；真尺寸 `image_dimensions` 头解析表（书级共享）。

### 1.4 资源占用量级（推算）

| 资源 | 量级 | 说明 |
| --- | --- | --- |
| 挂载 widget | 视口 1 屏 + overscan 2 页高 ≈ 3~5 个 `PageContent` | 已按需，健康 |
| 页内段落 widget | 每页 = 相交**完整段落**数个 | 长段落场景放大（见 2.1） |
| 行表对象 | 每行一个 `MeasuredLine`（5 字段对象） | 3MB 章 ≈ 5 万行 ⇒ 5 万小对象 |
| 页表 | 每页一个 `PageSlice` | 同上章 ≈ 数百~千页对象 |
| 正文文本 | 30 章 `ChapterContent.paragraphList` | 与页表行表双份驻留 |
| 图片 | 50MB 字节 + 未纳管解码位图 | 解码峰值不可控 |

## 2. 性能瓶颈清单（按严重度）

### 2.1 长段落整段重复布局（最大单点）

跨 k 页的段落，每页各持一份**完整段落**的 `InlineParagraph` → `RenderParagraph` 全量布局 k 次。`RenderParagraph` 布局缓存只在**实例复用**时生效，跨页是不同实例。极端：单段数万字符（TXT 无空行分段的粘连段）→ 每翻一页都把整段重新布局一遍。**章节过长 + 长段落 = 翻页掉帧的主源**。

### 2.2 测量单线程 + 顺序推进

- `dart:ui` 排版只能在 root isolate（`incremental_paginator.dart` 头注释），`TextPainter` 逐段排版，全章 O(n)。
- `IncrementalPaginator.step` **按段序推进**（段 0 → n）：目标在章中部时，落位依赖前缀测完（贪心切页前缀决定页界）。长章（MB 级）空闲帧 6ms/帧补完，全章定稿可能要数十秒级——期间超 5 页后的翻页会撞「页表未覆盖」。
- 页表前缀稳定性是上屏契约（除末页外边界不漂）——不能简单跳测，但**测量优先级**可以改（见 4.2）。

### 2.3 配置/图片失效太粗

- `PaginationScheduler.invalidateForImageSizes()`：一图真尺寸入表 ⇒ **清空全部缓存页表 + 作废全部任务**（`cache.clear()`）。图片多的 EPUB 在打开初期会反复全量重分页（每张图触发一次）。
- `PaginationConfig` 整体作废（改字号/转屏）⇒ 全清，旧页表不留——**回切无命中**。

### 2.4 窗口与预取偏窄

- 渲染窗口固定 ±1 章；±1 章预分页队列「当前章完成前不动邻章」（延迟一切非目标章工作）——**快速连续翻页**时，翻到 +2 章就是占位带（96dp），再等该章 prime。
- `kInitialPageCount = 5` 页才 `initialReady`；`kFirstPaintBudget = 16ms` 达标线偏后（首帧可更快：1~2 页即上屏即可读）。

### 2.5 其余次级

- `_headingHeightOf` 每次 `_buildPageViews` 对每章新建 `TextPainter` 测标题（build 期重复测量，可缓存）；
- 图片解码走 `Image.memory` 全局缓存，**无降采样、无限流**（连续图片同屏解码峰值）；
- 行/页对象为 5 字段 Dart 对象，长章 5 万行 ⇒ GC 压力（可 TypedData 紧凑化）；
- overscan 恒 ±1 页高：快速滚动时可见页频繁挂/卸，每页 build 重建段落 widget（build churn）；
- ListView 模式估高漂移（历史 bug 源），双通道长期并存是维护负担。

## 3. 按需渲染策略设计（目标形态）

**总原则：三级窗口 + 就近供给 + 离远即弃 + 结果复用。**

```
            ┌─ L0 可见带：视口 ±0.5 页高 ── 立即挂载、立即可画
窗口(章) ──┼─ L1 缓冲带：±2 页 ──────── 挂载 + 段 painter 就绪
            └─ L2 预测带：±1 章（翻页方向 +2）── 只测不画（页表/行表就绪）

章缓存：当前 ±1 常驻（保护），±2~±12 按距离补齐（现有 ChapterAutoLoader 复用）
页表：LRU 5 章保留（轻量），窗口外章的页表可留、段 painter 必须回收
```

### 3.1 渲染范围收紧

1. **页内渲染按行区间**（替换「完整段落 Column」）：`PageContent` 从「段落 widget 堆叠」改为「段落布局对象 + 只 paint 行区间」（详见 4.1）。这是渲染范围从 O(相交段长) → O(页行数) 的关键一步。
2. **overscan 分级**：慢滚/停稳 ±2 页（预挂），快速滚动（velocity 阈值）缩到 ±0.5 页（先卸后挂）；可见区间变化 < 半页不重挂（防 churn）。
3. **窗口 ±1 → 方向感知 ±(1~2) 章**：向后翻页中，next+1 章进入「只测不画」预测带；回翻对称。

### 3.2 快速回收

- **段 painter 池**：离远页卸载时，其段落布局对象进 LRU（按字节/条数上界，如 64 段），窗口内段落常驻——跨页共享同一 painter（同段跨 k 页只布局 1 次）。
- **行/页表**：轻量，保留 `PaginationCache` LRU 5 章语义不变（含保护集纪律）。
- **正文文本**：维持 `ChapterCache` 30 章上界（PERF-02 契约不动）。
- **解码位图**：接入显式上限（Flutter `PaintingBinding.imageCache.maximumSizeBytes` 按设备档位设限），离窗页的图可主动 evict。

### 3.3 流畅切换保障（翻页/滚动）

- 动画期 `freeze()` 只冻结**新测量**（保证③不动）；已就绪页的切换不受影响。
- 快速连续翻页：翻页方向队列 + 预测带预 prime；`_jumpPaged` 的 seq 作废机制保持（陈旧 clamp 丢弃）。
- 占位带 → 真页切换沿用语义重锚（`_applyPagedViews` 的 `chapterTops` 差补偿），**禁单跳像素修正**（现行红线不变）。

## 4. 可落地方案（三档）与自研渲染层可行性

### 4.1 A 档（推荐先做）：段落布局复用 + 行区间绘制

**关键结构**（新增 `lib/reader/pagination/paragraph_layout.dart`）：

```dart
/// 段落布局对象：整段一次 layout，跨页共享；只 paint 需要的行区间。
class LayoutedParagraph {
  final int paraIndex;
  final TextPainter painter;      // 整段一次布局（含占位尺寸）
  final List<double> lineTops;    // 行顶 y（与 MeasuredLine 对齐校验）
  final int refCount;             // 持有页数（归零即入 LRU）
}

class ParagraphLayoutPool {       // LRU：段下标 → LayoutedParagraph
  LayoutedParagraph acquire(int paraIndex, ...);
  void release(int paraIndex);
  // 上界按「段数 × 段长」字节估算，超限淘汰 refCount==0 的最久者
}
```

**渲染流程**：`PageContent.build` → 对页相交段落 `acquire`（命中 O(1)，未命中 layout 一次）→ 自定义 `RenderBox`/`CustomPainter` 用 `painter.paint(canvas, Offset(0, lineTop − preHeight))` 只画 `[页首行, 页末行]` 区间（行区间裁切用 `Canvas.clipRect`，不用重建 painter）。

**回收流程**：可见页卸载 → 相交段 `release` → refCount 归零入 LRU → 淘汰即 `painter.dispose()`。

**一致性保障**：行高来源仍是 `measureParagraphs` 的 `LineMetrics`（测量与绘制同一 painter 族，同宽同样式同缩放四支点不变）；新增对拍测试「整段 Column 渲染 vs 行区间绘制的行顶 y 全等」。

**收益**：长段落翻页成本从 O(段长) → O(页行数)；跨页同段布局 1 次；widget/element 数下降。

### 4.2 B 档：测量优先级 + 精准失效 + 布局缓存落盘

1. **测量优先级**（改 `PaginationScheduler`）：目标段落优先的「双向推进」——`IncrementalPaginator` 增加 `targetParagraph`，`step` 先测目标段（产目标页行表），再向后推进（保持前缀切页契约：目标**页界**仍需前缀，但目标段的**行高**先行可让「目标段所在局部页」先上屏，前缀补齐后走语义重锚合页）；实现上更稳的变体：**保持顺序测，但 prime 预算全砸到 target 覆盖为止**（现行已近似），补一条「target 段预热测量」跳过段间空段。取后者可零契约改动。
2. **图片精准失效**：`PaginatedChapter` 增记 `imageSrcs`（该章用到的图），`invalidateForImageSizes(src)` 只重分页含 src 的章，不清全缓存；配置失效（改字号）旧页表按 `configHash` 二级键**软保留**（回切命中）。
3. **布局缓存落盘**：行表/页表序列化进结构缓存（MRSC 加布局段，varint 编码 `MeasuredLine`/`PageSlice`）——重开书/重启免测量，直接命中（与 `BookSourcePool` 复用叠加 ⇒ 同书再开**零测量**）。**不落盘**段 painter（样式相关），落盘纯几何。
4. **标题测量缓存**：`_headingHeightOf` 结果按 (index, textStyle, scale) 缓存。

### 4.3 C 档：自研绘制层 / Rust 排版内核（可行性评估）

**结论：不必推倒重来——现行已具备自研渲染层约七成**（行表、页表、几何布局表、行顶对齐落位、可见区间挂载、语义坐标、缓存纪律都是自研组件），真正缺的只是**绘制后端**。三档对比：

| 路线 | 内容 | 工作量 | 风险 | 收益上限 |
| --- | --- | --- | --- | --- |
| A（推荐） | TextPainter 复用 + 行区间 paint | 2~3 批 | 低（有对拍测试锚） | 消灭长段重复布局 |
| B（推荐跟做） | 测量优先级 + 精准失效 + 布局落盘 | 2 批 | 低 | 冷启动免测量、图片书不再全清 |
| C1 全自绘 | Canvas 字形 run 自绘（行表→字形定位） | 大 | 中高：选区/高亮/TTS 跟随/link hitTest 全要自研 | 帧成本最低、可控性最高 |
| C2 Rust 内核 | 排版/测量下放 Rust（绿野 §2.4） | 大 | 高：`RUST-09` 固化「排版分页不上 Rust」，须走变更流程 + 先测后引 | 测量 3~10×、布局产物可落盘 |

建议执行序：**A → B →（观测指标）→ 决定是否上 C**。若 A+B 后「长章翻页 P95 帧耗时」与「冷启动测量耗时」达标，C 档缓行；C1 与 C2 不必并行，若走 C 优先 C2（复用绿野方案的数据面设计），C1 的 hitTest/选区成本是隐藏大坑。

### 4.4 复用与预加载机制汇总

| 机制 | 现状 | 改造后 |
| --- | --- | --- |
| 章正文 | `ChapterCache` LRU 30 + 距离补齐 | 不变 |
| 页表 | `PaginationCache` LRU 5 + 保护集 + 按 bookId 驻留 | + configHash 软保留 + 落盘（B 档） |
| 段落布局 | 无（每页重建） | **`ParagraphLayoutPool` LRU**（A 档核心） |
| 图片字节 | `ImageCacheLRU` 50MB | 不变 |
| 图片解码 | 全局无界 | 显式上限 + 离窗 evict + 限流 2 |
| 预分页 | ±1 章（当前章完成后） | 方向感知 ±(1~2)，预测带「只测不画」 |
| 首屏 | 5 页才 `initialReady` | **目标页 1 页即上屏**（`initialReady` 放宽为目标覆盖，5 页线移入后台目标） |

## 5. 边界情况与处理

| 边界 | 现状风险 | 处理 |
| --- | --- | --- |
| **章节过长**（MB 级单章） | 5 万行 `MeasuredLine` 小对象 GC 压力；全章定稿慢 | 行表 TypedData 紧凑化（start/end/height/para 四列 int/f32 数组）；测量优先目标段；超长段切片（段 > N 行时按行组虚拟分段，仅渲染层切，语义偏移不动） |
| **超长段落**（单段跨多页） | 每页整段重复布局（2.1） | A 档段 painter 复用 + 行区间 paint |
| **图片加载** | 一图入表清全缓存；解码峰值 | 精准失效（4.2-2）；解码限流 + 降采样到目标尺寸；失败 48×48 占位不阻塞（已有） |
| **快速连续翻页** | 跨章撞占位带；动画期积压测量 | 方向感知预测带 + prime 优先；动画结束 `stepIdle` 续排（已有）；`_jumpPaged` seq 作废（已有） |
| **占位→真实切换** | 布局突变跳动 | 语义重锚保持（红线）；占位语义不换真标题（§2.74 判据不动） |
| **转屏/改字号** | 全清缓存、回切重排 | configHash 软保留旧页表（B 档） |
| **空段章/孤行章** | 永驻占位 | 真身判据=「内容+页表就绪」不看段落数（已有，保持） |
| **快速滚动** | 可见页 churn | 区间变化 < 半页不重挂 + 分级 overscan |
| **图片章（ListView 通道）** | 估高漂移 bug 源 | 中期目标：图片章并入分页通道（图片高已同步可知），单一渲染路径 |

## 6. 性能验证指标（可量化、可打点）

| 指标 | 目标 | 测法 |
| --- | --- | --- |
| 首次出字 | 热 ≤ 150ms / 冷 ≤ 600ms（`open.firstText`） | 真机 20 次 P50/P95 |
| 目标页就绪 | ≤ 1 帧（`paged.prime` 首页） | 打点 |
| 翻页帧耗时 | P95 ≤ 8ms（120Hz）；连续翻 30 页 1% low ≥ 90fps | 帧时间线 |
| 长段落翻页 | 跨 k 页同段场景帧耗时与 k **无关**（A 档判据） | 构造 50KB 单段夹具 |
| 滚动期 build/layout | build ≤ 4ms、layout ≤ 2ms 每帧 | DevTools timeline |
| 测量预算遵守 | 6ms/帧超帧率 < 5%（`[perf]` 打点） | 真机日志 |
| 冷启动免测量 | 重开书页表命中率 ≥ 90%（B 档 `layout.cacheHit`） | 打点统计 |
| 图片精准失效 | 一张图入表 ⇒ 重分页章数 = 1 | 单测断言 |
| 内存稳态 | 阅读页 RSS ≤ 150MB；3MB 长章峰值 ≤ 200MB；快滚 10 屏后回落 | DevTools memory |
| 回收及时性 | 跨章滚动后窗口外段 painter 数 = 0（池上界内） | 单测断言 |

**判红纪律**：每条指标配会变红的验收用例；修复后回头确认历史用例仍具判别力（防「恒绿护栏」）。
