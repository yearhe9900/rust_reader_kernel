# 极速开书全链路设计：导入 · 打开 · 渲染

> 一份不受现有实现约束的绿野设计方案。参照 legado（原生排版引擎）、Anx Reader（Flutter + foliate-js 混合栈）、foliate-js（浏览器端分页器）三家的真实设计逻辑，回答一个问题：**如何把「导入一本书 → 从书架点开 → 读到内容」做到极致快速、全程不卡顿。**
>
> 三阶段各自独立成章：先说这一阶段哪些环节最伤流畅度，再给核心思路、数据流转、性能优化要点，最后统一汇总瓶颈与规避方式。

---

## 0. 设计目标与总原则

### 0.1 体验指标（性能预算，先定数字再谈方案）

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 点书卡 → 首次出字 | 热启动 ≤ 150ms（P50）/ ≤ 300ms（P95） | 「热」= 该书近期开过，布局缓存/结构缓存可用 |
| 点书卡 → 首次出字（冷） | ≤ 600ms | 「冷」= 首次打开、大书（20MB+ TXT / 大 EPUB） |
| 翻页 / 滚动稳态 | 120Hz 零掉帧（1% low ≥ 90fps） | UI 线程单帧工作 ≤ 4ms，动画期零排版 |
| 章边界翻页 | ≤ 30ms 出字 | 相邻章必须已在缓存 |
| 导入上书架可点 | ≤ 500ms | 书卡立即出现（可先用文件名 + 默认封面） |
| 导入全量精修 | 后台完成，不阻塞任何交互 | 分章/字数/封面/目录/搜索索引 |
| 内存稳态 | 阅读页 ≤ 150MB（含图） | 缓存有硬上限且可预测 |

### 0.2 五条总原则（后文所有决策都从这里推导）

1. **关键路径零「全量」**：整本书级的解压、分章、排版、索引，一律不得出现在打开一本书的关键路径上。
2. **UI 线程只做合成与绘制**：解析、解压、文本测量、排版、图片解码全部在后台执行体（isolate / worker thread）完成，UI 线程只消费结果。
3. **三级交付**：把「打开」拆成 *看见（瞬时反馈）→ 可读（估算上屏）→ 精排（增量替换）* 三级目标，逐级交付，绝不让用户盯着空白等待一个「完美首帧」。
4. **预测代替等待**：预热、预取、预排，把成本挪到「用户还没需要」的时刻；需要时只是取缓存。
5. **一切中间产物可缓存、可增量、可中断**：缓存 key 必须覆盖 *内容 × 样式 × 视口* 三要素；任何后台任务可取消、可续做、幂等。
6. **计算面与呈现面分离（执行体内核）**：解析、解压、测量、分页、缓存等**计算面下放 Rust**（无 GC、可并行、可控内存布局、产物可序列化）；合成、手势、动画等**呈现面留在 Flutter**（Skia/Impeller 本就是原生）。详见 2.4。

## 1. 三阶段流畅度关键环节剖析

先定位「卡」从哪来。三阶段的性能杀手完全不同，混在一起谈优化必然失焦。

### 1.1 导入阶段：伤在 IO 与全量扫描

| 环节 | 为什么伤流畅度 | 量级 |
| --- | --- | --- |
| 文件搬运（拷贝进应用目录） | 大文件顺序写，占满 IO 带宽，拖累前台 | 100MB 级 |
| 格式嗅探与解压 | zip 整解、MOBI HUFF/CDIC 解压极慢（foliate-js 明确指出 KF8 解压慢） | 10~1000ms×N |
| TXT 编码检测 + 分章 | 全文件扫描 + 正则匹配，单线程做就是秒级卡死 | 全书 O(n) |
| 元数据 / 封面提取 | 封面图片解码 + 缩放，峰值内存 | 数十 ms~数百 ms |
| 入库建索引 | 事务批量写、全量索引构建 | 数百 ms~秒级 |

**要害结论**：导入阶段的正确目标不是「快点导完」，而是**「立刻可点、后台精修」**——用户对「导入完」的感知是书出现在书架上，不是索引建完。

### 1.2 打开阶段：伤在串行依赖与文本测量

| 环节 | 为什么伤流畅度 | 参照系 |
| --- | --- | --- |
| 多路数据串行读取 | DB → 文件 → 解析 → 渲染一条线排队，每段都等上一段 | 传统实现最大浪费 |
| 进度恢复坐标换算 | 「字符偏移 → 屏幕位置」需要排版结果，天然循环依赖 | legado/Anx 都在这里丢帧 |
| 首章文本获取 | 解压/读盘 + 清洗规则 | 数十~数百 ms |
| **排版 / 分页（文本测量）** | **整条链路最大 CPU 杀手**：逐字宽测量、断行、分页 | legado 整章 StaticLayout/ZhLayout；foliate-js 的 CSS multi-column 自述 "it's slow" |
| 首帧资源 | 字体加载、封面解码、shader 首次编译 | 常被忽略的一次性抖动 |

**要害结论**：打开阶段慢，十有八九不是「读盘慢」，而是**把「排完一整章」当成出字的前提**。必须把排版从「打开的前置条件」降级为「打开后流式补齐的工作」。

### 1.3 渲染阶段：伤在每帧成本与布局抖动

| 环节 | 为什么伤流畅度 | 说明 |
| --- | --- | --- |
| 每帧绘制成本 | span/列数过多、逐字 draw、图片未预解码 | 翻页掉帧主因 |
| 动画/手势期触发重排 | 拖动、翻页动画中重新测量 → 布局抖动 + 掉帧 | 所有阅读器的共同痛点 |
| 翻到未排版页 | 页边界处等待排版 → 「翻页卡一下」 | legado 用三页工厂 + 预载缓解 |
| 长章节内存与缓存淘汰 | 单章数 MB 文本一次性成对象 → GC 抖动 | 大 TXT 单章场景 |
| 图片解码峰值 | 连续图片同时解码，抢占 CPU/带宽 | 漫画/CBZ 尤甚 |

**要害结论**：渲染流畅 = **动画期零布局 + 绘制成本恒定 + 相邻页永远就绪**。为此必须把「排版结果」变成不可变的、可预生成的对象，让翻页退化为「切换对象 + 变换」。

## 2. 总体架构

### 2.1 分层

```
┌──────────────────────────────────────────────────────────┐
│ UI 壳层        书架 / 阅读页 / 设置（只做合成、手势、动画）   │
├──────────────────────────────────────────────────────────┤
│ 会话层         ReadingSession（一次"打开一本书"的生命周期）   │
│                TaskScheduler（优先级 + 可取消 + 并发流水线）  │
├──────────────────────────────────────────────────────────┤
│ 引擎层(Rust)   FormatAdapter（EPUB/TXT/MOBI/PDF/CBZ…）     │
│                ChapterSource（按章供字节/文本 + 权重）       │
│                ContentProcessor（清洗/规则，离线化）         │
│                LayoutEngine（测量/断行/分页 = 纯函数）        │
│                RenderScene（不可变页对象 + 绘制指令）          │
├──────────────────────────────────────────────────────────┤
│ 存储层         LibraryStore（元数据/进度/配置，WAL 数据库）   │
│                ContentStore（分章压缩块，随机读）            │
│                CacheStore（结构缓存 / 布局缓存 / 缩略图）     │
└──────────────────────────────────────────────────────────┘
```

关键点：**引擎层整体是 Rust 内核**（见 2.4），与 UI 层之间只传零拷贝不可变对象（页对象、章节块、语义坐标）。UI 层永远不直接触碰文件、压缩包或解析器。

### 2.2 数据流转总览

```
 书文件 ──导入──▶ BookRecord(元数据) + ChapterIndex(章索引)
                  + ContentStore(分章压缩块) + Thumbnail(缩略图)
                              │
 书架点卡 ──打开──▶ ReadingSession.open(bookId)
                              │  并发：进度 / 配置 / 章索引 / 目标章块
                              ▼
                  LayoutEngine（后台流式产页，估算占位 → 精排替换）
                              │
 首帧 ◀──三级交付── 快照贴图 → 估算页 → 精排页（原地替换，位移 < 1 行）
                              │
 渲染 ◀── RenderScene（页对象 = 预录绘制指令）── 翻页/滚动只做变换
                              │
                  相邻页/相邻章持续预排（低优先级队列）
```

### 2.3 核心数据结构（决定一切性能的骨架）

| 结构 | 内容 | 设计意图 |
| --- | --- | --- |
| `BookRecord` | 书名、作者、封面引用、格式、内容哈希、导入状态 | 书卡渲染不依赖任何正文 |
| `ChapterIndexEntry` | 章标题、**字节范围/字符范围**、字数（权重）、锚点 | 打开任一章 = O(1) 定位，不扫描全书 |
| `ContentChunk` | 单章（或单逻辑块）压缩后的字节块 | 随机读、低内存、可预读 |
| `LayoutPage` | 行 → span（文本切片 + 样式 + 基线）+ 绘制指令，**不可变** | 翻页零排版；可整体缓存/序列化 |
| `SemanticPos` | `(chapterId, charOffset)` | 进度真值；与视口/字号无关 |
| `PixelPos` | 滚动像素偏移 | **仅缓存**，用于毫秒级复位 |
| 缓存 key | `contentHash × styleHash × viewportHash` | 样式/窗口变化精确失效，不失效过宽 |

### 2.4 执行面：Rust 内核 + Flutter 壳（「用 Rust 替代 Dart」的正确落法）

直觉正确：**计算密集的热路径用 Rust 写，比用 Dart 写更快、更稳**。但要替代的是**计算面**，不是呈现面——Flutter 的合成/动画/光栅化本来就是 C++（Skia/Impeller），这部分换语言零收益；Dart AOT 也不是解释执行，纯胶水代码换 Rust 意义不大。真正的收益来自四件事：

1. **无 GC、可控内存布局**：排版产生海量小对象（行/span/字形位置），在 Dart 堆上是分配压力与 GC 停顿之源；Rust 侧 arena + 紧凑结构，帧时间可预测。
2. **批量化执行**：一次 FFI 调用吃进「一章/一块字节」，吐出「一个页窗口的布局结果」，绝不行级/字形级跨界。
3. **真并行**：rayon 线程池并行排多个块、并行预排相邻章，既不占 UI 线程也不占 Dart isolate。
4. **布局产物可序列化**（最实质的一条）：SkParagraph/TextPainter 的排版结果**不可序列化、跨会话即失效**；Rust 自控布局结果用 rkyv 归档落盘 = mmap 即用，**冷启动免排版**。这是「Rust 更快」里最持久的收益。

**边界划分**：

| 下放 Rust（计算面） | 留在 Flutter（呈现面） |
| --- | --- |
| 格式解析（zip 中央目录、OPF、MOBI/KF8 解压、TXT 流式分章） | 书架 / 阅读页 UI、转场 |
| 编码检测与转码（chardetng + encoding_rs） | 手势识别、翻页/滚动动画（只做变换） |
| 内容清洗（规则管线，离线化） | 图层合成、玻璃/阴影等视觉效果 |
| 文字整形与排版（rustybuzz/HarfRust + parley 或 cosmic-text） | 字形光栅化可复用 Skia（回传字形 run） |
| 断行/BiDi/CJK 分行（ICU4X / unicode-linebreak） | 阅读设置、统计等 UI |
| 分页与页窗口调度（rayon，优先级 + 可取消） | 生命周期、平台通道 |
| 布局/结构缓存（rkyv 零拷贝落盘与加载） | |
| 图片解码/降采样（image + fast_image_resize） | |

**数据面（零拷贝是硬要求）**：

- 内容与布局结果统一为 **rkyv 归档字节**（归档布局 = 内存布局，访问 = 指针偏移）；磁盘缓存 mmap 后直接当 Rust 对象读，加载 ≈ 0 成本；
- FFI 只传 `(ptr, len)` / TypedData 视图；span 引用原文切片，Dart 侧只读展示、不解析；
- 字符编码：边界统一 **UTF-8 字节 + 字节偏移**语义坐标；Dart String（UTF-16）只在显示局部文本时临时换算，杜绝全书级 UTF-8⇄UTF-16 转换；
- 句柄化 API：Rust 侧持有 `BookEngine` / `ChapterSource` / `LayoutWindow` 句柄；panic 不跨边界（catch_unwind + 错误码），生命周期由 Rust 托管。

**线程模型**：Rust 自有线程池（rayon，N-1 worker），按优先级消费任务（可见页 > 相邻页 > 预取章 > 后台索引），任务可取消；完成经事件端口通知 Dart，UI 线程零等待。

**生态落点**：

| 能力 | Rust 组件 |
| --- | --- |
| 文字整形 | rustybuzz / HarfRust（HarfBuzz 移植） |
| 排版 / 断行 / BiDi | parley（Fontique + Skrifa + ICU4X）或 cosmic-text；CJK 断行走 unicode-linebreak / ICU4X |
| 编码检测/转码 | chardetng + encoding_rs（Firefox 同源） |
| 压缩/归档 | zip（随机访问）/ flate2 / zstd |
| 零拷贝序列化 | rkyv（布局缓存/结构缓存） |
| 并行调度 | rayon + 优先级队列 |
| 图片 | image + fast_image_resize |
| 可选 GPU 通道 | vello / tiny-skia（低端机整页栅格化） |

**预期收益**（相对纯 Dart 引擎，热路径 CPU 折算）：解压/解析 2~5×、测量分页 3~10×（并行 + 无中间对象 + 无 GC）、布局缓存加载 ≈ 0（mmap）；首帧路径 FFI 往返 ≤ 2 次。

**风险与规避**：

- FFI 边界滥用（逐行/逐字形跨界）会把收益吃光 → 纪律：一次调用 = 一个完整任务，只回传扁平字节；
- 双工具链（cargo + Flutter）构建矩阵与调试成本 → 引擎 crate 独立测试与基准先行，Flutter 侧只做薄绑定；
- unsafe / panic 边界 → 可选 bytecheck 校验、catch_unwind、句柄托管；
- 自研排版对复杂 CSS EPUB 覆盖不足 → 保留 WebView/foliate-js 类引擎为冷格式降级通道（见 §9）；
- 纯文本小书收益有限 → 仍走同一引擎统一路径，不为小书单独维护一条 Dart 路径。

## 3. 阶段一：导入图书

### 3.1 核心思路：导入 = 建索引，不搬运正文、不排版

**两阶段导入**，把「可点」和「精修」彻底解耦：

**Stage A — 秒级上架（目标 < 500ms，同步感）**

1. 文件入库：优先**移动或硬链接**而非拷贝（同卷零拷贝）；跨卷才流式拷贝（后台）。
2. 格式嗅探：读魔数 + 扩展名，确定 `FormatAdapter`。
3. **只读结构，不读内容**：
   - EPUB：只读 zip 中央目录（一次 IO），得到 spine → 条目映射；读 OPF 拿书名/作者。
   - TXT：只做编码检测（见 3.3）+ 头部采样估计分章风格。
4. 写入 `BookRecord`（状态 = `indexing`），书卡立即上架：文件名作占位书名、默认封面。
5. 队列投递 Stage B 任务（低优先级、可取消、幂等）。

**Stage B — 后台精修（秒级到分钟级，全后台）**

- 精确分章 + 章标题抽取；
- 全书字数/权重统计（供进度与预排预算）；
- 封面解码 + 生成缩略图（书卡只用缩略图，不用原图）；
- 生成**结构缓存**（TOC、章内锚点、坐标映射）；
- 可选：全文搜索索引（分片、增量）；
- 全部产物落 `ContentStore` / `CacheStore`，完成事件通知书卡刷新。

### 3.2 数据流转

```
原始文件 ──(移动/硬链)──▶ 库文件区
   │  Stage A：嗅探 + 结构读取（1 次 IO）
   ▼
BookRecord(indexing) ──上架──▶ 书架书卡（占位封面/标题）
   │  Stage B：后台队列（可取消/幂等/断点续做）
   ▼
ChapterIndex(全量) + ContentChunk×N + Thumbnail + 结构缓存
   │  事件总线
   ▼
BookRecord(ready) ──▶ 书卡精修（真封面/真字数/进度条可计算）
```

### 3.3 各格式导入策略

- **TXT**：`mmap`/分块流式扫描，**只扫每行行首 N 字符**跑分章状态机（正则预编译），记录**字节偏移**而非复制字符串。编码检测顺序：BOM → UTF-8 合法性校验 → GB18030/GBK 采样（前 64KB 统计判别），结论写入 `BookRecord` 全书复用。巨型单章（无章节标记）按固定字符数切**逻辑块**，每块独立成 `ContentChunk`。
- **EPUB**：zip 随机读依赖中央目录（foliate-js 的 zip loader 就是这个思路：支持随机访问、不整载内存）；条目**按需流式 inflate**，绝不预先解压全书。CSS 只取影响排版的最小集（字号/行距/缩进/对齐），媒体类型白名单。封面取 OPF `cover-image` 元数据，缺失时取 spine 首图。
- **MOBI/AZW3**：foliate-js 的教训直接吸收——MOBI **一次性解压后按 `<mbp:pagebreak>` 切段**（它明确说这样做「drastically improves rendering performance」）；KF8 按需解压但 HUFF/CDIC 很慢 ⇒ **导入期就把 KF8 转成标准段落流 + ContentChunk**，把解压成本从「每次打开」挪到「一次导入」。
- **PDF/CBZ/CBR**：只建页级索引（页尺寸、字节范围），首页预渲染成缩略图；正文页按需渲染 + 预读 ±2 页。

### 3.4 性能优化要点

1. **零搬运**：同卷移动/硬链接，避免 100MB 级拷贝。
2. **结构先行**：zip 中央目录、EPUB OPF、TXT 行首采样——都是 O(结构) 而非 O(内容)。
3. **正文留在原地**：能随机读就不改写（EPUB）；必须改写的（MOBI/KF8）改写一次、之后永远随机读。
4. **分章压缩块**：每章独立压缩（zstd/deflate），随机读 O(1)，内存占用与章大小无关。
5. **封面走缩略图管线**：解码 + 降采样 + WebP/AVIF 缓存，书架永不碰原图。
6. **任务队列一等公民**：导入任务持久化、断点续做、重复导入按 `contentHash` 去重。
7. **写路径不阻塞读路径**：数据库 WAL，Stage B 批量写事务合并。

### 3.5 本阶段瓶颈与规避

| 瓶颈 | 成因 | 规避 |
| --- | --- | --- |
| 大文件拷贝 | 顺序写 IO | 移动/硬链接；跨卷拷贝丢后台并显示进度 |
| zip 全解 | 预解压全书 | 只读中央目录 + 按需 inflate |
| KF8/HUFF 解压慢 | 算法本身慢 | 导入期一次性转标准段落流 |
| TXT 全文件正则 | 逐字符匹配 | 行首采样 + 状态机 + 字节偏移 |
| 编码误判 | 采样不足 | BOM→UTF-8 校验→GB18030 采样三级判定，结论缓存 |
| 封面解码峰值 | 大图进内存 | 限流队列 + 降采样 + 只存缩略图 |
| 入库事务风暴 | 逐章一事务 | 批量合并写 + WAL |

## 4. 阶段二：从书架打开图书

### 4.1 核心思路：三级交付 + 并发流水线 + 记忆化

打开一本书不是一个瞬间，而是三级目标逐级交付：

| 级别 | 目标 | 预算 | 实现 |
| --- | --- | --- | --- |
| **L1 看见** | 点击即时反馈，书「打开」了 | ≤ 1 帧 | 书卡点击反馈 / 过渡动画；阅读页先贴**版式快照** |
| **L2 可读** | 有字可读，位置正确 | ≤ 150ms | **估算排版**上屏（字数 × 均值行高估算行位置），语义坐标精确 |
| **L3 精排** | 精确版式、图片、页码就位 | ≤ 500ms 稳态 | 精排结果**原地替换**估算页，位移控制在 1 行内，语义重锚零跳动 |

### 4.2 关键路径并发流水线

```
open(bookId)
 ├─ IO   ：进度 + 配置 + 章索引（已在内存/结构缓存）      ┐ 并行
 ├─ IO   ：目标章 ContentChunk 解压                       ├ 并行
 ├─ CPU  ：清洗（规则替换，若导入期已做则零成本）           ┘ 并行
 ├─ CPU  ：排版目标页（只排落位页 ±2）          ← isolate  │ 流式
 └─ UI   ：首帧合成（快照 → 估算页 → 精排页 crossfade）   ┘ 主线程

后台续排（低优先级）：±2 页 → 当前章剩余 → 相邻章 → 预测章
```

要点：
- **四路并发**，谁先到谁先用，不互相等待；
- 排版**只排落位页 ±2**，绝不「排完一章才显示」——这是与 legado 整章排版（`ChapterProvider` 把一章排成完整 `TextChapter`）最大的分野；
- 任务有**优先级与取消**：用户一旦跳章/跳转，低优先级预排全部让路。

### 4.3 版式快照恢复（把「秒开」变「瞬开」的关键）

- 每次**离开阅读页/停稳**时保存最后视口的「版式快照」：低分辨率位图（或绘制指令回放）+ `SemanticPos` + 样式指纹 + 视口指纹；
- 开书先贴快照（L1），再用估算页/精排页无缝替换；
- 快照指纹命中（同书同样式同窗口）→ 用户视觉上是「书一直在」；不命中（改了字号/换了设备）→ 快照降级为模糊底图，仍优于空白。

这是 legado 与 Anx Reader 都没有做的一层：两者开书都要等真实的排版结果（legado 等 `TextChapterLayout`，Anx 等 WebView + foliate-js 分页），而快照让首帧**不依赖任何排版工作**。

### 4.4 记忆化与命中

- 布局缓存 key = `contentHash × styleHash × viewportHash`：同参数重开 → 布局缓存命中，**O(1) 取页**，排版成本归零；
- 样式变化（改字号）→ 只失效布局、不失效结构与内容缓存；
- 视口变化（转屏/改窗口）→ 只重排可见页，旧缓存保留（回切即命中）；
- 进度写盘节流（停稳才写），且**未收敛不写盘**（语义坐标优先，像素仅缓存）。

### 4.5 语义坐标与落位

- 进度真值 = `(chapterId, charOffset)`，像素偏移只是加速缓存；
- 程序化落位（开书、跳章）：**行顶对齐**；
- 自然停手/复位：**保留像素余量**，避免「手一松字就跳」；
- 估算页 → 精排页替换时必须**语义重锚**（按 `charOffset` 重新定位），禁止用像素差做单跳修正——那是阅读器最常见的「闪跳」根源。

### 4.6 书架侧预热：把打开成本前置到「浏览时」

- 书卡滚入视口 / 悬停 / 获得焦点 → 低优先级预热：解析器实例、元数据、**首章 ContentChunk 预读**、甚至目标页预排；
- 只预热「即将进入视口」的 2~3 本，节流 + 可取消，避免预热风暴；
- 效果：用户点卡时，首章内容已在内存，打开路径只剩「取页 + 贴图」。

### 4.7 本阶段瓶颈与规避

| 瓶颈 | 成因 | 规避 |
| --- | --- | --- |
| 串行依赖 | DB→文件→排版→渲染排队 | 四路并发流水线，结果流式消费 |
| 整章排版才出字 | 把排版当打开前提 | 只排落位页 ±2，其余后台流式 |
| 快照/真页替换跳动 | 像素修正 | 语义重锚，位移 < 1 行 |
| 首帧字体加载 | 字体未就绪导致二次排版 | 度量对齐的 fallback 字体（同字宽基线），字体就绪后零位移替换 |
| 冷盘慢 IO | 首次读盘 | 预读窗口（±1 章）+ 结构缓存常驻 |
| 大书首章巨大 | 单章 MB 级 | 逻辑块化，只解压落位块 |
| 预热失控 | 大书架全量预热 | 视口节流 + 优先级队列 + 可取消 |

### 4.8 冷启动预载：把「冷」变「温」（预加载是冷启动最有效的手段）

冷启动慢的本质是「什么都要从零做」。与其一味优化冷路径，不如**提前把书预载成『开书就绪包』**，让冷启动退化为「取用」：

**开书就绪包（Book Ready Bundle）** = 结构缓存 + 目标章 ContentChunk（解压后）+ 进度与配置 + 布局缓存（最近视口页）+ 版式快照 + 字体度量。任一书持有此包，打开即直达 L2（≤ 150ms，与热启动同级）。

**预载时机（按优先级）**：

1. **App 启动后 idle**：预载「最近在读 3~5 本」的就绪包——把绝大多数真实会话从冷变温的关键一招；
2. **书架渲染时**：可见书卡 + 即将进入视口的 2~3 本（见 4.6）；
3. **阅读中**：当前书的相邻章，以及「下一本可能读」（同作者/同系列/上次未读完）；
4. **闲时补全**：充电 / 空闲 / 锁屏前，后台补全最近书目的布局缓存与快照；
5. **导入完成时**：新书顺势生成就绪包（导入 Stage B 顺手做，零额外成本）。

**代价控制**：

- 内存预算：就绪包常驻 ≤ 3~5 本（约 20~40MB），LRU 淘汰；布局缓存/快照可只 mmap 不驻内存（rkyv 零反序列化，见 2.4）；
- 全部低优先级、可取消，被用户打开动作抢占；
- 预载深度只到「落位页 ±2」级别，不做全书。

**效果预期**：冷启动路径从「解压 + 分章 + 排版 + 渲染」缩为「取包 + 贴图」；≤ 600ms 的冷启动预算只留给**从未预载的书**（全新导入 / 极老书目），预载过的书按热启动口径（≤ 150ms）。

## 5. 阶段三：渲染图书

### 5.1 核心思路：排版是纯函数，绘制是预录指令

把排版定义为纯函数：`layout(text, style, viewport) → LayoutPage[]`。纯函数意味着**可缓存、可后台计算、可流式替换、可并行**。渲染阶段只消费不可变的 `LayoutPage`：

- **分页模式**：当前页 ±2 页就绪即可（legado 的 `TextPageFactory` 维护 prev/cur/next 三页是同一思想，本方案扩展为窗口 + 预排）；
- **滚动模式**：视口 ±2 屏，按**行块**（约 30 行）懒排；块高先用估算值占位，精排后原地修正 + 语义重锚；
- **长章节**：切成逻辑块独立排版/缓存，禁止整章一次性成对象；
- **翻页 = 切换页对象 + 变换**（平移/卷曲/覆盖动画都是对同一绘制指令做变换），动画期**零布局、零测量**。

### 5.2 三级缓存体系

| 层 | 内容 | 策略 |
| --- | --- | --- |
| L1 内存页缓存 | 当前章 ±1 章的 `LayoutPage` | LRU + **保护窗口**（视口所在章永不淘汰；全保护则不淘汰） |
| L2 磁盘布局缓存 | 序列化的行/页布局（key 三要素） | 冷启动命中即免排版；容量上限 + LRU |
| L3 源数据缓存 | `ContentChunk` + 结构缓存 + 缩略图 | 常驻（体积小），随书生命周期 |

### 5.3 绘制

- **Canvas 自绘**而非 widget 树逐段 build：每页绘制指令预录（display list），绘制成本与页内容复杂度线性且恒定；
- span 引用原文切片（不复制字符串），行对象池复用；
- 阴影/渐变等高成本效果烘焙进指令或降级，保证单帧绘制 ≤ 4ms；
- 可选：整页栅格化缓存（静态页只画一张位图，翻页只做位图变换），代价是内存，按设备档位开关。

### 5.4 图片

- 解码在后台 isolate，**解码即降采样**到目标显示尺寸（防止 GPU 纹理超尺寸）；
- 解码队列限流（并发 2），动画期间只贴占位、停稳再补真图；
- 低清模糊占位 → 真图 crossfade；解码失败 → 占位降级，不阻塞翻页。

### 5.5 手势与动画解耦

- 拖动/滑动期间**只做像素变换**（Transform），不触发任何测量；
- 停稳后才做「余量保持」的重锚与余下预排；
- 翻页动画用两页绘制指令做合成动画；模拟翻页等重效果按设备档位降级为平移；
- 手势识别、动画曲线、排版调度三者独立线程/独立优先级，互不阻塞。

### 5.6 字体

- 内嵌字体按章子集化（subset）加载；
- 字体未就绪时使用**度量对齐**（字宽/基线一致）的 fallback，保证替换时零位移；
- 用户自选字体走同一管线，度量信息进 `styleHash`。

### 5.7 内存与 GC

- 页对象/行对象/绘制指令对象池；
- 帧内分配预算 < 4KB，杜绝动画期大 List/String 分配；
- 图片缓存上限（如可用内存 25%）；
- 大字符串一律切片引用，跨 isolate 传 `TypedData`/偏移量而非大字符串拷贝。

### 5.8 本阶段瓶颈与规避

| 瓶颈 | 成因 | 规避 |
| --- | --- | --- |
| 每帧绘制过重 | span 多、逐字 draw | 预录绘制指令 + 恒定成本 + 可选整页栅格化 |
| 动画期重排 | 拖动触发布局 | 变换与布局解耦，停稳才重锚 |
| 翻页到未排页 | 页边界等待 | 页窗口预排 + 相邻章预取 |
| 长章节内存爆炸 | 整章成对象 | 逻辑块化 + LRU + 保护窗口 |
| 图片解码峰值 | 同屏多图同解 | 限流 + 降采样 + 占位 |
| 字体替换跳动 | fallback 度量不一致 | 度量对齐 fallback |
| GC 抖动 | 帧内大分配 | 对象池 + 帧内分配预算 |
| 缓存失效风暴 | 改字号/转屏 | 三要素 key + 只排可见 + 旧缓存保留 |

## 6. 数据流转一览（阶段 × 输入 / 执行体 / 输出 / 存储）

| 阶段 | 输入 | 执行体 | 输出 | 落到哪 |
| --- | --- | --- | --- | --- |
| 导入 A | 原始文件 | 主线程（限 500ms）+ Rust IO worker | BookRecord(壳) | LibraryStore |
| 导入 B | 文件 + 结构 | Rust rayon 后台队列 | ChapterIndex / ContentChunk / 缩略图 / 结构缓存 | ContentStore / CacheStore |
| 打开 | bookId + 点击事件 | Rust 引擎（IO×2 + rayon 排版）+ UI 合成 | 三级首帧（快照→估算→精排） | 内存页缓存 |
| 预载 | idle / 书架 / 闲时 | Rust 低优先级队列 | 开书就绪包 | 内存 LRU + mmap 缓存 |
| 渲染 | LayoutPage + 手势 | UI（变换）+ Rust（预排/预取） | 每帧画面 / 进度事件 | 布局缓存(L2) + 进度(LibraryStore) |

跨阶段的三条不变式：
1. UI 线程**从不**解压、从不测量文本、从不解码图片（这三件事全在 Rust 内核，见 2.4）；
2. 任何时刻都有「可显示的东西」（快照 / 估算页 / 精排页三者至少其一）；
3. 所有后台工作可取消，取消代价 O(1)（只丢弃未消费结果）。

## 7. 性能预算表（热 / 冷）

| 环节 | 热启动预算 | 冷启动预算 | 备注 |
| --- | --- | --- | --- |
| 点击反馈 + 过渡 | 1 帧 | 1 帧 | 同步 |
| 进度/配置/章索引读取 | ≤ 5ms | ≤ 30ms | 结构缓存常驻 |
| 目标章块解压 | ≤ 5ms | ≤ 30ms | 单块 ≤ 256KB |
| 估算排版（落位页） | ≤ 10ms | ≤ 30ms | 后台 isolate |
| 精排（落位页 ±2） | 缓存命中 ≈ 0 | ≤ 200ms | 后台流式 |
| 首帧合成 | 1 帧 | 1 帧 | 主线程 |
| **合计（出字）** | **≤ 150ms** | **≤ 600ms** | |

两点口径说明：
- CPU 预算按 Rust 内核（§2.4）折算：测量/分页预算已含 3~10× 加速与并行余量，FFI 往返 ≤ 2 次计入首帧；
- 冷启动预算（≤ 600ms）默认假定该书**未被预载**；被预载过（就绪包命中，§4.8）的书直接按热启动口径。

## 9. 与 legado / Anx Reader / foliate-js 的设计逻辑对照

| 维度 | legado（原生排版） | Anx Reader（Flutter + foliate-js） | 本方案取舍 |
| --- | --- | --- | --- |
| 排版引擎 | `ChapterProvider` + `TextChapterLayout`，StaticLayout / 自研 ZhLayout，可选两端对齐 | WebView 内 CSS multi-column 分页（foliate-js 自述 "it's slow"），bisect 找可见 Range | 自绘排版纯函数，只排可见块；吸收 legado 的「行/列实体」思想，放弃其整章排版 |
| 打开流程 | 查缓存 → 取内容 → 规则清洗 → 异步整章排版 → 显示 | WebView 引导 → 本地 HTTP 供书 → JS 分页 → relocate 事件 | 四路并发流水线 + 三级交付 + 版式快照 |
| 页管理 | `TextPageFactory` prev/cur/next 三页 + 预载相邻章 | paginator 内部 anchor 锚定，resize 不丢位置 | 页窗口（±2）+ 保护窗口 LRU + 语义锚定（吸收 foliate-js 的 anchor 思想） |
| 章节供给 | 内容缓存 + 网络书源加载 | sections 接口：`load()` 按需给 URL、`size` 供进度，资源按需加载 | `ChapterSource` 同构抽象：按章供块 + 权重（吸收 foliate-js 的 book 接口） |
| 大文件策略 | 章节级缓存 | zip 随机访问、不整载内存；MOBI 整解后按 pagebreak 切段 | 分章压缩块；MOBI/KF8 导入期转标准段落流 |
| 进度 | 章内页码 + 字符位置 | CFI / fraction，relocate 事件 | `SemanticPos(chapterId, charOffset)` 真值 + 像素缓存 |
| 内容清洗 | 规则管线（打开时执行） | JS 端转换 | **清洗前移到导入期离线执行**，打开零成本 |
| 动画 | delegate：Cover/Slide/Simulation/Scroll | paginator animated 属性滑动 | 绘制指令 + 变换，动画期零布局 |
| 执行体 | Kotlin + StaticLayout(C++) + Canvas | JS 引擎（WebView） | **Rust 内核（计算面）+ Flutter（呈现面）** |

三条最值得吸收的设计逻辑：
1. **foliate-js 的 book 接口**（`sections.load()/unload()/size`）——把「章节供给」抽象成可按需加载、可释放、带权重的流，是所有格式统一进引擎的前提；
2. **legado 的行/列实体与三页工厂**——把页面物化为不可变对象，翻页才可能零成本；
3. **Anx Reader 的读写并发**（SQLite WAL + 本地 HTTP 流式供给）——写路径（同步/统计/进度）永不锁读路径。

一条明确要避开的路线：**CSS multi-column 分页**（foliate-js/Epub.js 同款）——实现快但自述慢、样式兼容差、测量不可控；它适配格式广，不适合「极致流畅」目标。若需要它的格式覆盖力，可作为**冷格式降级通道**（少见格式走 WebView 引擎），主链路保持自绘。

旁证与执行体结论：重渲染的阅读器几乎都把计算面放在原生内核（SumatraPDF=C++，KOReader=C+MuPDF）；过去 Rust 的短板是文字排版生态，如今 parley（Fontique + HarfRust + Skrifa + ICU4X）与 cosmic-text（rustybuzz + fontdb + swash）已把整形、断行、BiDi、字体回退补齐——这正是本方案敢用 **Rust 内核做排版**（§2.4）的前提。

## 10. 降级与验收

### 10.1 诚实降级（快不动时怎么办）

| 场景 | 降级 |
| --- | --- |
| 格式解析失败 | 退纯文本流式阅读 |
| 布局缓存损坏 | 隔离该项缓存、现场重排（缓存损坏 ≠ 判据失效） |
| 图片解码失败 | 占位块，不阻塞翻页 |
| 极低端设备 | 关整页栅格化/重动画，保留三级交付与页窗口 |
| 预排跟不上 | 估算页兜底（永远有字可读） |

### 10.2 验收口径

- **打点**：`open.snapshot` / `open.firstText` / `open.laidOut` / `layout.cacheHit` / `page.move.d` 等关键事件全部带耗时；
- **真机**：热/冷各 20 次取 P50/P95，大书（100MB TXT / 大 EPUB / 带图 EPUB）分别测；
- **帧率**：滚动与翻页各 60s，1% low ≥ 90fps（120Hz 屏）；
- **内存**：连续翻 50 章后 RSS 稳定、无锯齿增长；
- **判据用例**：每个瓶颈配一条会变红的验收用例（防止「修复让历史用例静默失去判别力」）。

## 11. 与现行 MReader 设计的异同（对照备忘）

一句话结论：**方向高度同源**——现行 MReader 已经把「关键路径零全量、并发开书、语义坐标、保护窗口、预热下一章」这条主线走起来了，绿野方案大量条目与之逐句一致；真正的增量集中在三处：**执行面（Rust 计算面）、首帧策略（三级交付 + 版式快照）、缓存层次（布局缓存落盘 + 就绪包预载）**。

### 11.1 相同 / 同源（现行已具备）

| 现行设计 | 绿野方案（对应章节） | 关系 |
| --- | --- | --- |
| 语义坐标 `(chapterHref, chapterPos)` 为真值，像素仅缓存、未收敛不写盘 | §2.3 / §4.5 | 逐句同源 |
| 落位二分：程序化=行顶对齐、自然停手=保留像素余量（`keepScrollRemainder`）、布局突变=语义重锚禁单跳 | §4.5 | 设计直接沿用现行口径 |
| 开书并发：progress/prefs 与书源解析并发、bookmarks 与元数据/封面 inflate 移出首帧（§2.107） | §4.2 四路并发 | 方向一致，设计更进一步（估算上屏） |
| 窗口尾追加即刻**预热下一章**（legado「预载下一章」语义） | §5.1 页窗口 + 相邻章预取 | 同源 |
| `BookSourcePool`：导入即入池 + 关书回池 ⇒ 同书再开零读盘零解析（§2.108） | §4.4 记忆化 / 热启动 | 同精神；现行复用「解析器 + 章节表」，不含排版产物 |
| 结构缓存 MRSC（varint 二进制，schema 2） | L3 结构缓存 | 同思路；设计统一到 rkyv |
| 进度权重廉价化 `chapterWeightEstimates()`（zip 中央目录零解压，§2.75） | 「导入建索引不搬内容」 | 同一条纪律：禁止全量扫描 |
| 分页缓存保护窗口 `setProtected`、全保护不淘汰（§2.80） | L1 保护窗口 LRU | 一致 |
| 未分页章 96dp 占位块（§2.74） | 「永远有可显示的东西」 | 同精神，设计升级为三级交付 |
| 诚实降级（缓存损坏隔离重算、损坏≠判据失效） | §10.1 | 一致 |
| 打点与判红纪律（`[perf]`、变异判红先确认判别力） | §10.2 | 一致 |

### 11.2 不同（绿野新增 / 与现行相反）

| 维度 | 现行 MReader | 绿野方案 | 影响 |
| --- | --- | --- | --- |
| **执行面** | Dart 主导 + Rust 仅档位 3（检索+解析）；**`RUST-09` 固化：排版分页/持久化/统计/网络/简繁/图像不上 Rust**（排版依赖 TextPainter） | 计算面全 Rust（含排版分页、rkyv 缓存、图片），呈现面留 Flutter（§2.4） | **最大分歧**：测量分页 3~10×、布局产物可落盘、无 GC 抖动 vs FFI 纪律与双工具链 |
| **首帧策略** | 放行门闸（§2.85：精确落位收敛 / `_viewportReal` / 调度器驻留）收敛后才出真页，**防闪优先** | 三级交付：快照→估算→精排，**出字优先**，靠语义重锚保证替换不跳 | 取舍相反：现行稳但首帧晚，设计快但要解决替换不跳 |
| **版式快照** | 无 | §4.3 关书存快照、开书先贴 | 「瞬开」关键层 |
| **布局缓存落盘** | 无（MRSC 只存结构；排版结果不落盘，重开重排窗口） | L2 rkyv 布局缓存 + mmap（§5.2） | 冷启动免排版 |
| **预载** | 预热下一章 + 解析器池 | 就绪包五时机预载最近 3~5 本（§4.8） | 冷变温 |
| **导入** | 导入即解析入池（成本前置、一次到位） | 两阶段：壳 ≤500ms 上架 + 后台精修，建索引不搬内容（§3.1） | 大书导入体验 |
| **图片/字体** | 封面 inflate 移出首帧；PERF-02 解析后释放非章节资源 | 解码即降采样、限流、低清占位、度量对齐字体 fallback（§5.4/5.6） | 细化 |
| **渲染模式** | 整章连续渲染 + 分页调度窗口（禁页边界吸附） | 双模均块/页窗口懒排 + 估算占位→精排（§5.1） | 现行占位是几何块，设计占位是内容估算 |
| **冷格式通道** | 无（PDF=pdfrx 2.6.5，MOBI/AZW3 P2） | foliate-js/WebView 冷格式降级通道（§9） | 格式覆盖策略 |
| **工程红线** | 玻璃态红线、setState 唯一、池三纪律、测试基线 | 刻意不带（绿野） | 落地须回接红线 |

### 11.3 若往现行迁移：按收益/成本排序

1. **低成本高收益（不碰红线）**：就绪包预载（把「预热下一章」扩为「预载最近书」）、导入两阶段壳化、图片降采样管线。
2. **中成本（动首帧哲学，需拍板）**：三级交付/估算上屏 + 版式快照——与现行「门闸防闪」取舍相反；落地必须复用 §2.85 的同一几何真值做替换不跳（否则闪动回潮）。
3. **高成本（动 `RUST-09`，走变更流程）**：Rust 计算面。与现行「先测后引、只读链路」并不冲突——可按档位推进：先测「解析+解压+分章」基准，再进「测量分页」，基准数据达标才上 rkyv 布局缓存。

## 附：一页速记

- **导入**：建索引不搬内容，壳先上架、后台精修；MOBI/KF8 的解压痛挪到导入期一次。
- **打开**：三级交付（看见→可读→精排），四路并发，只排落位页 ±2；版式快照 + 记忆化 = 瞬开。
- **渲染**：排版纯函数、页对象不可变、动画只做变换；三级缓存 + 保护窗口 + 语义锚定。
- **贯穿**：UI 线程零重活、后台任务可取消、缓存 key 三要素、一切进度走语义坐标。
- **执行面**：计算面（解析/解压/测量/分页/缓存）= Rust 内核（rayon 并行、rkyv 零拷贝、布局缓存可落盘）；呈现面（合成/动画/手势）= Flutter。一次 FFI = 一个任务。
- **冷启动**：预载「开书就绪包」（最近在读 3~5 本：结构 + 章块 + 布局缓存 + 快照），冷变温；≤ 600ms 冷预算只留给从未预载的书。
